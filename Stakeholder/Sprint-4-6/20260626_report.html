三、之前遗留的技术债处理

遗留问题风险本阶段处理
Android 连接体验债用户会遇到连接卡住、误报网络被阻挡、切线状态闪烁等问题。集中修复延迟探测、重连、免费额度、活动弹窗和连接状态显示。
网站部署和路由债静态站点部署路径不清，Nginx 配置过散，容易出现路由漂移。完成生产 Nginx routing 清理，并标准化三个静态网站 CI/CD。
基础设施安全债旧机器、旧日志、旧 artifacts 和数据库公网暴露会增加排错与安全风险。生产 MySQL 已无公网 IP，旧文件和日志清理进入持续整理。
后端 all-in-one 债主后端、BO、cron 长期混在一起，后续 FFF 复用会继承同一套包袱。BO 与 cron 已拆出，公共工具和迁移流程正在抽离。
Windows 旧客户端债旧客户端接旧后端接口，签名路径过期，无法稳定发新版。已开始升级到最新后端 API，并整理 Docker 构建和云签名路线。

四、改善与商业价值

改善当前结果商业价值
Android 稳定性连接、延迟探测、活动弹窗、重连和文案问题持续收尾。降低用户误判网络被封锁、连接卡住和切线失败的概率。
多协议测试后端多协议支持已放到测试环境给 QA 验证。后续可按地区和网络环境切换更合适协议，提高连接成功率。
数据库安全生产 MySQL 已无公网 IP，仅保留私网访问。数据库不再直接暴露互联网，安全风险明显降低。
网站发布Nginx routing 与静态网站 CI/CD 已标准化。官网、landing 和下载入口发布更可控，减少人为部署错误。
成本节省LisaHost HK 机器已退订，Azure 当前 run-rate 明显下降。成本节省已有实际依据，后续等完整账单再做月结确认。
后端通用化公共工具开始从三个后端 repo 中抽离。减少重复代码，为 FFF 后端复制和后续扩展做准备。
Windows Docker 化Windows 构建路径开始改为可复现的 Docker 流程。降低本地环境差异，方便生成测试版和正式版。

说明：成本口径沿用 2026-06-25 内部刷新。Azure 与 LisaHost 属于直接持续节省；AWS 是替代原本本地 GitLab、runner 和生产网站，并新增 CI/CD 与日志观测能力的平台成本，不合并为直接节省。

五、安全与访问控制

项目本阶段变化价值
生产数据库MySQL 已无公网 IP，仅通过私网和受控通道访问。降低数据库被直接扫描和攻击的风险。
