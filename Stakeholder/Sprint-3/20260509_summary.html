四、节点与后台自动化（本阶段最大的运维杠杆）

★ 现场实测（5/10）— 测试环境全部 7 台节点跨 3 大洲并行回收

单次后台 API 调用同时触发 7 台节点全擦重装（中国 / 香港 / 越南 / 菲律宾 / 丹麦 / 加拿大 / 法国）：最快 15 秒（Vancouver 175 ms RTT 最远反而最快）· 最慢 44 秒（广州 ACME 走 GFW）· 整批端到端 44 秒 · 0 失败。

真正的赢面不是「44 秒」，而是「学习曲线归零」 — 接手时要翻文档、判断节点系统、选进程管理器、SSH 跑命令、看日志验证（老员工也要开手册）；现在勾「全擦重装」→ 选主机 → 点确认即可，第一天报到的新人都能做。同时消除「关键人物风险」、统一了节点池上 7 种不同的进程管理装法。

五、大重构 + 堆灭的风险与滥用

大重构堆灭的具体风险 / 滥用
  • 免费配额信任链反转（客户端记账 → 节点驱动）
  • 节点配置单源化（YAML 散落 → 后端唯一可信来源）
  • 节点进程管理统一（PM2/systemd/Docker → systemd 单一）
  • USDT 支付 Java→Go 重写（黑盒 → 源码可审）
  • 节点身份重构（数字 ID → main_ip 自注册）
  • 后台 SPA 流水线独立化（admin 失败不再阻塞后端发布）
  • 后端 CI 重构（6 阶段 → 4 阶段单一职责，4-6 倍提速）
  • 移动端架构清理（utilcodex / Compose / 三星 / Gradle 模块合并）
  • 移动端工具链跃升（Gradle 9 / Kotlin 2.3 K2 / AGP 9.1 / Java 22）
  • 节点防火墙单一来源（三套并存 → apply-iptables.sh）
  • 协程崩溃保护（顶层 recover + safego 包装）
  • 跨端关联日志（X-Request-ID 端到端）
  • UUID 抽取 = 无限免费 VPN → 关闭（节点驱动配额）
  • 挂时长绕过抽奖在线时长 → 关闭（节点统计真实通信）
  • 免费注册跨账号串号 + ASN 段滥用 → 关闭
  • IAP 续订代币不推进（扣款不发 VIP） → 修复
  • 专线到期不释放节点（节点池虚耗） → 修复
  • iptables NAT 表脏数据（连接不稳隐性故障） → 自动清理
  • 数据库无任何自动备份（区级故障即丢库） → 已开启 Azure 自动每日
  • 读副本「有但没用」（主库压力大） → 切到读副本
  • HK 旧 ProxyBackend 长期不稳定（每次请求多一跳） → 退出关键路径
  • USDT 支付黑盒（jar 无源码） → Go 重写，源码可审
  • 节点 7 种装法漂移（运维负债） → systemd 单一
  • swagger 文档过期（移动端依赖错的契约） → 自动从代码生成
  • sing-box 二进制依赖 GitHub（中国封锁失败） → 本地镜像 + SHA256
  • 滥用观察原始 IP 落地（违无日志承诺） → 节点端单向哈希，仅计数上报

★ 业务安全核心改造 — 免费额度由「客户端记账」改为「节点记账」

接手时移动 App 自己计时免费时长，再「告诉」后端 — 任何修改 App / 抓包伪造汇报的人都能拿到无限免费 VPN。本阶段把这条信任链整体反转：由 VPN 节点（服务器侧）按真实流量计时，节点每 30 秒上报，后端是唯一可信来源。

维度改造前改造后
谁说了算移动 App 自己计时VPN 节点上报真实流量，后端是唯一可信来源
UUID 被抽取=「无限免费 VPN」后端可即时撤销账号，节点立即踢出
挂 VPN 不用计时仍累积不产生流量 = 不计时
抽奖在线时长客户端可被绕过由节点统计真实通信时长

对业务的保护：关闭 Trojan UUID 提取漏洞 · 消除「挂时长」绕过 · 免费额度展示与真实一致 · 守住付费转化率（约 5%）的护城河 · 节点级真实数据为后续转化优化与采购决策打基础。
